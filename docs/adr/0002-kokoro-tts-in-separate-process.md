# 用 sherpa-onnx 运行 Kokoro 语音合成，放在独立进程里

为了让通话对方直接听到译文，需要把译文合成语音。我们选择 Kokoro 多语言模型 v1.1（一个模型覆盖中英两个翻译方向），通过 sherpa-onnx 在 CPU 上离线运行。用的是 fp32 版本（目录约 408 MB）而不是 int8 版本（约 206 MB）：在 Ryzen 5 5600 上实测，int8 版本的实时率约 1.35 到 2.2，比实时还慢，增加线程也没用；fp32 版本 4 线程时实时率约 0.34 到 0.43。这是项目的第三套推理依赖（onnxruntime）。

Kokoro 念英文时依赖 espeak-ng 做音素转换，而 espeak-ng 是 GPL v3。软件目前只在内部使用、不对外分发，所以 GPL 暂时不构成约束。即便如此，合成部分仍放在一个独立的辅助进程里，主程序通过管道发文字、收音频：以后如果要对外闭源分发，许可边界已经划好，只需请律师确认这种进程隔离是否足够，不够时再改用不依赖 espeak-ng 的英文音素方案。独立进程还有一个好处：合成崩溃不会带走识别和注入。

备选方案：Windows 自带语音（SAPI/OneCore）零体积、无许可问题，但声音偏机械；Piper 很快很小，但中文声音弱，而且同样依赖 espeak-ng；CosyVoice、F5-TTS 这类能克隆音色的大模型在 CPU 上做不到实时。没有选用的语音识别替代品 Whisper 与这一步无关。
